最终要交付的完整链路

平台管理身份、业务主体、调用应用和数据源凭据分别建模。应用上限、主体策略、Agent / 数据集 / 任务范围共同收窄，任何范围配置都不能额外授予数据权。

  1. 业务系统完成用户认证

    MEPER 验证 Client、Issuer、受众、时效与重放；会话绑定客户端、身份来源、主体、模型和权限域。外部 admin 不自动成为平台超管。

  2. 数据库目录解析业务主体

    按已发布映射解析业务键、角色、组和类型化属性。目录源可以独立于资源源；缺映射、停用、歧义或必需属性缺失时拒绝。

  3. 在单个明确权限域内形成有效授权

    同一身份模型可复用于多个域，一个域可管理多个资源源。产品操作与数据读取分别决策；跨库执行仍逐库取授权交集，不自动跨域合并。

  4. 受控查询、知识检索与服务端计算

    元数据、SQL、Wiki、数据集和结果工作区共用边界。查询结果治理后才能进模型；输出血缘覆盖别名和派生结果，脱敏字段不能用于推断或计算。

  5. 敏感正文缓冲，复验后交付

    关键步骤重读外部身份和本地授权；最终交付前复验全部来源。正文、reasoning、工具结果、图表、引用等可能承载敏感内容的出口统一处理；实时进度仅含非敏感状态。

  6. 历史与再次消费重新授权

    结果 handle、缓存和历史按主体 / 所有者、授权戳、范围与知识版本复验；取消或预算超限保留真实状态，不将部分结果标成完成。

身份与资源配置通用

业务库无需改造成固定 tenant_id / department_id / sys_user 结构。首版以两套异构目录验证配置通用性；不按姓名或 email 自动跨来源合并主体。

工程边界统一

web 只适配协议；domain 编排；policy 纯决策；query-enforcement 解析与治理；连接器负责连接与执行。Agent、Wiki 和历史消费受控结果，不建立第二条执行路径。

上线门禁与验收范围

单表权限通过不代表整产品通过；配置页完成也不能代替真实数据库操作与撤权验收。

可信接入与身份隔离

两套异构目录、相同 sub 不串权、身份源与资源源分离；签名冒用、过期、重放及错误域请求拒绝。

行列执法与最严合并
