## 1. 交付边界

- 业务数据库只经 MetadataService 读取结构、经 WorkbenchService 执行查询，不写表/字段备注、不存 Wiki 表。
- 控制库追加 V7 六表：对象镜像、字段镜像、Wiki 页面、不可变发布版本、资源绑定、同步记录。
- 已占用 V1–V6；权限迁移必须在实际最新序号后追加，不能沿用旧 P2 计划的 V6。
- session-wiki → control-storage（传递 connector-spi），domain → session-wiki 编排结构采集；agent → session-wiki，Web 消费 domain/Wiki 服务，不直连业务库。
- 当前身份体系仅引导管理员：WikiAccess 在服务层按已验证主体检查，正式 P2 要替换为实时资源/字段决策，不能把当前版本宣称为多用户权限产品。

## 2. 主要页面

入口 `/datawiki`，沿用现有主题。数据源切换 + 左侧库表/文档目录 + 内容编辑 + 右侧详情。

| 视图 | 行为 |
| --- | --- |
| 概览 | 对象数量、有效发布知识、缺少描述的字段、待复核知识；点击进入对应处理列表 |
| 库表知识 | 原始备注只读；业务名称、描述、粒度、别名、时间、过滤、注意事项；补充 Markdown |
| 字段 | 行内编辑名称/描述/单位；详情抽屉编辑枚举、别名、时间及注意事项；按缺少描述/单位筛选 |
| 业务文档 | 指标、术语、关联、分析规则模板；显式关联表/字段，发布前校验依赖 |
| 发布与历史 | 保存草稿、发布前左右内容比较、不可变历史、恢复到新草稿、停用；表/字段一起发布 |
| 搜索 | 字面搜索发布知识，支持路径过滤及分页；点击按版本局部读取 |
| 同步记录 | 命名空间/单表采集，结果数量、失败记录；失败不覆盖镜像 |

工作台表结构的「业务说明」直达目标表；AI 对话工具的「已读取」引用打开对应版本抽屉。

## 3. 一致性与检索

- 草稿保存使用 draftVersion 乐观锁；控制库数据源行锁串行化编辑、发布与镜像落库。
- 发布快照包含正文、资源指纹、可恢复的编辑状态；读历史不改变现有结构。
- 镜像采集先完成全部指定范围读取，再事务写入；人工语义与结构分离，重复同步不覆盖说明。
- 对象/字段消失仍保留说明；只有完整成功的范围采集才判断消失。结构变化标记依赖页面需复核，复核发布前退出检索。
- Agent 工具：wiki_glob（路径发现）、wiki_grep（字面搜索）、wiki_read（指定版本局部读取）。虚拟路径不访问磁盘，不开放 shell/任意正则。
- 默认只检索正式、未停用、结构有效版本；所有管理与读取先校验主体/数据源，绑定不能跨数据源。
- 每轮最多 12 次 Wiki 调用、累计 32000 字符；单次搜索最多 20 条，读取最多 100 行/16000 内容字符。
- system prompt 只含检索规则，全文由工具按需返回；实时表结构仍需 get_table_schema 验证。
- 暂不含向量搜索、批量导入、模型自动生成说明、多人审核和外部 CLI 文件挂载；均不影响首版人工建设和检索闭环。

## 4. API

统一前缀 `/api/datasources/{ds}/wiki`：

- GET `pages` / `objects` / `pages/{id}`；POST `pages`；PUT `pages/{id}`。
- POST `pages/{id}/publish`、`/restore`、`/disable`；GET `pages/{id}/revisions`。
- POST `sync`（namespace、可选 table）；GET `sync-runs`。
- GET `search`（query、pattern、cursor、limit）；GET `read`（path、revision、start、count）。

## 5. 人工验收路径

1. 登录，在 DataWiki 选测试数据源，按命名空间同步结构。
2. 打开 orders：填写「一行一个订单」；paid_amount 填「实付金额，单位为分」；status 填枚举。
3. 保存草稿：搜索应搜不到新说明；查看差异并发布后，应能搜到并按版本读取。
4. 新建「净收入」指标：关联 orders.paid_amount、refunds.refund_amount，说明退款先按订单聚合；保存、发布。
5. 继续改草稿：已发布内容保持不变；旧编辑版本提交返回 409。
6. 再同步相同结构：人工说明保留，不产生无效复核提醒。
7. 在测试业务库改变字段结构后同步：表说明及指标都进入待复核，退出 Agent 搜索；复核发布后恢复。
8. 查看历史与恢复到草稿：历史保留；当前数据库结构不回退；停用后正式搜索不可见。
9. AI 对话提问指标定义：查看 wiki_grep/read 调用与版本引用，确认没有首轮全量 Wiki 注入。
10. 核对业务库的表备注、字段备注和原数据未被 Wiki 编辑改变。

## 6. 验证策略

集中执行一次 Maven 全量 package；新增真实 MySQL 8.4 生命周期集成用例覆盖草稿/发布、并发版本、原库无副作用、跨数据源、失败采集、结构失效、历史恢复与停用。模型协议夹具真实驱动 Spring AI 的 grep→read 循环，不请求外部模型。前端做 TypeScript/生产构建与页面人工链路核对。只在新改动或明确失败时做针对性重测。
